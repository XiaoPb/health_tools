# analyze 命令

自动编排数据检查、准确度评估、原始信号诊断和必要的离线 PSD 分析，输出结构化明细、证据图和中文报告。别名：`ana`。

```bash
ghealth_tool analyze -i <输入CSV或结果目录> -o <输出目录> [options]
```

| 选项 | 说明 |
|---|---|
| `-i, --input` | 原始 CSV 文件/目录，或已有 offline 结果目录 |
| `-o, --output` | 分析输出目录；已有核心产物时拒绝覆盖 |
| `--type` | `hr`、`spo2` 或 `other`，默认 `hr` |
| `--rule` | analysis 规则文件；`other` 类型必填 |
| `--chip` | 芯片型号；无法从信息行识别时必填 |
| `--scene` | `auto`、`static`、`dynamic`，默认 `auto` |
| `--sample-rate` | 覆盖采样率 Hz |
| `--ref-column` | 覆盖参考值列 |
| `--pred-column` | 覆盖算法结果列 |
| `--timestamp-column` | 指定时间戳列 |
| `--focus` | 强制深度分析的带目录 glob，可重复；零匹配直接失败 |
| `--report` | `markdown`、`pptx` 或 `all`，默认 `all` |
| `--offline-version` | 离线算法版本；未指定时使用芯片默认版本 |
| `--no-offline` | 禁止自动离线 PSD 升级 |
| `--workers` | 数据检查工作数，默认 4 |
| `--accuracy-thresholds` | 固定准确度阈值，逗号分隔，默认 `5,10,15` |
| `--accuracy-inclusive/--accuracy-strict` | 阈值边界包含/严格模式；默认 strict，即 `abs(error) < threshold` |
| `-v, --verbose` | 显示文件级结果 |

## 处理阶段

原始 CSV 先执行完整性、参考值、信号质量和准确度检查。普通文件在证据足够时结束；`--focus` 文件无论正常与否都会继续所有适用阶段。证据不足时，心率分析会把文件复制到输出工作区，再按指定或默认版本调用离线算法并分析 PPG/ACC PSD。源文件不会被移动或覆盖。

分析优先复用现有命令的 Python API，不启动 Click 子进程：

1. `check` 判断范围、帧、时间戳、ACC、居中和 Ipd 转换等基础数据问题；只有 `FAIL` 会进入异常归类，`WARNING` 保留为检查提示。
2. `evaluate` 提供逐文件准确度指标，合并 MAE、RMSE、标准差、相关性和有效样本数。
3. `plot` 生成报告证据图。原始信号与结果对比使用 `time`，运动或低灌注证据使用 `ac`，血氧关键证据默认使用 `ac`，离线时频证据统一使用 `psd`。
4. 心率文件在结论为“证据不足”或无法确定关键图表时优先离线升级，并引用 `plot --type psd` 的 PNG。显式使用 `--no-offline` 时报告会记录未执行原因。

报告只引用支撑当前原因的关键图。普通正常文件不额外生成图；异常文件、`--focus` 文件和已有 PSD 证据的“证据不足”文件才进入证据页。帧或时间戳异常无法由 `plot` 表达时，才单独生成采样间隔图。

## 判断流程与依据

分析按以下顺序执行，后续阶段不会覆盖优先级更高的可靠证据：

1. **输入可信度**：识别芯片信息行、列名、采样率和时间轴。采样率优先使用 `--sample-rate`，其次从时间戳推导，最后使用 analysis 规则的 `sampling.sample_rate`；无法可靠确定时停止依赖采样率的检测。
2. **基础数据检查**：调用 `check`。范围、帧、时间戳、ACC、居中和 Ipd 转换只有 `FAIL` 才作为异常原因；`WARNING` 只保留为提示。报告会引用 check 的说明、异常次数、最长连续帧和前 10 个异常帧位置。
3. **原始光学信号**：检查缺失、平线、饱和、基线漂移、通道一致性和运动幅度。`CH*` 默认按 Rawdata 解释；`CH*`/`Rawdata*` 计算 PI 前减去 chip 规则的 `chip_info.adc_offset`，`Ipd*` 已是 pA，不减 ADC 偏置。PI 只在静止场景使用，动态场景不把 PI 作为证据。
4. **参考数据**：检查参考值范围、有效比例、跳变和长时间不变化。Polar 局部异常只生成需人工复审的警告，并从准确度样本中隔离；全局分析、原结论和关键图表继续保留。只有 Polar 全局不可用或有效比例低于门槛时，才停止基于参考值的错误归因并输出“证据不足”。
5. **准确度和异常分段**：调用 `evaluate` 并计算逐样本绝对误差、MAE、最大误差、动态阈值占比以及持续异常区间。
6. **心率 PSD 证据**：普通文件仅在证据不足时升级，`--focus` 文件强制升级。离线算法只处理输出工作区副本；时频图统一由 `plot --type psd` 生成。SpO2 和未声明 `hr_psd` 的自定义规则不会使用心率锁频检测。
7. **结论合成**：按原因优先级匹配结构化条件，依次输出参考数据问题、原始数据问题、算法异常机制、算法性能极限、未发现异常或证据不足。

结论依据遵循以下优先级：

| 情况 | 结论 | 依据与限制 |
|---|---|---|
| Polar 局部越界、跳变或可疑停滞 | 保留原分析结论 + Polar 警告 | 异常位置不参与准确度；警告要求人工复审，不作为错误归因 |
| Polar 全局不可用或有效比例不足 | 证据不足 | 禁止基于 Polar 评价算法性能，要求人工复审 |
| 非 Polar 参考值越界、缺失或长期不变 | 参考数据问题 | 不使用该参考值评价算法性能 |
| 原始数据异常且存在采集措施 | 原始数据问题 | 给出佩戴、静止、遮光、采集链路或时间对齐措施 |
| 原始数据异常但没有可行改善措施 | 算法性能极限 | 说明适用场景，不给算法优化建议 |
| 原始与参考正常，算法误差异常且 PSD/时域证据充分 | 算法异常机制或算法性能极限 | 只说明锁频、牵引、谐波、跳变等可能机制 |
| 所有适用检查正常 | 未发现异常 | 列出已完成的检查范围 |
| 缺列、缺采样率、缺 PSD 或证据冲突 | 证据不足 | 列出缺失项；心率优先尝试附 PSD 图 |

## SpO2 静止测试约束

SpO2 只支持静止测试。三轴 ACC 合成幅度的归一化波动达到 `motion_rms` 阈值，或显式指定 `--scene dynamic` 时，直接报告“SpO2 仅支持静止测试，当前运动幅度过大”，即使当前算法值与参考值一致也不会判为正常。证据图默认使用 `plot --type ac`，并给出保持受测者、佩戴部位和设备静止后重新采集的措施。

血氧原始数据还会检查低灌注相关信号质量、双波长平线或饱和、红光/红外一致性、基线漂移、遮光和佩戴变化。静止场景下以有效光学通道中的最低 PI 与 `pi_low` 比较，任一关键通道低于门槛即报告低灌注。算法原因仍只说明可能机制，不输出算法优化或调参建议。

## 配置判断阈值

内置规则位于 `rules/analysis/analysis_hr.yaml` 和 `analysis_spo2.yaml`。建议复制到用户规则目录后修改，不直接改包内文件：

```bash
ghealth_tool config --init
ghealth_tool validate ~/.ghealth_tools/rules/analysis/custom_spo2.yaml
ghealth_tool analyze -i data/ -o analysis/ --type spo2 \
  --rule ~/.ghealth_tools/rules/analysis/custom_spo2.yaml
```

常用阈值及影响如下。数值是内置默认值；“更严格”表示更容易报告异常，不代表算法性能发生变化。

| 阈值 | HR | SpO2 | 判断与配置影响 |
|---|---:|---:|---|
| `missing_ratio` | 0.01 | 0.01 | 全表缺失或断帧允许比例；调低会更容易判数据不完整 |
| `flat_ratio` | 0.98 | 0.98 | 通道等于首值的比例达到该值判平线；调低更严格 |
| `saturation_ratio` | 0.01 | 0.01 | 达到 ADC 满量程 98% 的样本比例；调低更严格，仅在 chip 提供满量程时生效 |
| `baseline_drift_ratio` | 0.50 | 0.50 | 首尾均值差相对信号跨度的比例；调低更容易报告基线漂移 |
| `pi_low` | 0.50 | 0.50 | 静止场景 PI 低于该值判低灌注；SpO2 使用有效光学通道的最小 PI，调高更严格，动态场景不使用 |
| `motion_rms` | 0.10 | 0.10 | ACC 合成幅度标准差相对中位幅度；调低更容易判动态，SpO2 超限直接判测试条件不满足 |
| `error` | 10 bpm | 3 | 单样本绝对误差阈值；调低会增加异常样本和异常分段 |
| `error_min_seconds` | 5 | 5 | 异常至少持续的秒数；调高会过滤更短的瞬时误差 |
| `ref_min` / `ref_max` | 30 / 220 | 70 / 100 | 参考值有效范围；收窄范围会隔离更多局部样本 |
| `ref_valid_ratio` | 0.80 | 0.80 | 有效参考样本占比下限；调高后更容易判参考全局不可用 |
| `ref_stale_seconds` | 120 | 120 | 参考值连续不变的最长允许时长；调低更容易判参考停滞 |
| `ref_jump_per_second` | 20 | 5 | 参考值每秒最大跳变量；超限位置隔离并警告，调低更严格 |
| `jump_per_second` | 20 | 5 | 算法结果折算到每秒的最大跳变量；调低更容易报告跳变 |
| `channel_correlation` | - | 0.30 | 双波长相关性低于该值判不一致；调高更严格 |
| `psd_clarity` | 3 | - | 心率 PSD 峰值相对频谱基线的清晰度；调高会要求更清晰的主峰 |
| `psd_lock_hz` | 0.20 | - | PPG 与 ACC 主频差小于该值计为锁频；调高更容易命中锁频 |
| `psd_pull_hz` | 0.50 | - | 锁频阈值之外、该值以内计为频率牵引；调高扩大牵引范围 |
| `psd_presence` | 0.60 | - | 清晰 PPG 峰出现帧占比；调高更容易判峰断裂或宽频噪声 |

阈值修改后先运行 `ghealth_tool validate`，再用已知正常和已知异常的小样本各验证一次。阈值只改变诊断和归因的敏感度，不能用于绕过“算法原因不提供优化建议”的限制。

## 输出

- `analysis_summary.json`：完整特征、原因、证据、警告和结论。
- `file_diagnosis.csv`：逐文件结论摘要及独立警告列。
- `segment_diagnosis.csv`：异常时间段。
- `figures/`：每个文件的证据图。
- `analysis_report.md`、`analysis_report.pptx`：按 `--report` 生成。
- `stages/`：check、evaluate 和离线升级的中间产物。

## 准确度统计口径

原始数据评估、已有 PSD、自动 offline 升级、结构化 CSV，以及 Markdown/PPT 报告始终使用
同一组 `--accuracy-thresholds` 和 strict/inclusive 配置。默认阈值为 `5,10,15`；strict
模式按 `abs(error) < threshold` 计入，指定 `--accuracy-inclusive` 后改为
`abs(error) <= threshold`。CSV、Markdown 和 PPT 的阈值列随实际配置动态生成，不固定为
`±5/±10/±15`。

准确度输入列如果没有任意一个 finite 且非 `0` 的值，则整列禁用，不参与边界、比较或
汇总。剩余全部启用列共同确定首尾共享边界，即首个和最后一个“所有启用列均为 finite 且
非 `0`”的行；所有列使用同一切片。切片中间的 `0` 保留并参与正常误差计算，`NaN`/`Inf`
仅在每个比较对象成对计算时过滤。

PSD 中 Polar 启用时，为所有启用的 Online、Offline、Comp 分别计算 `vs Polar`；Polar
禁用时，只有 Online 和 Offline 均启用才回退为 `Online vs Offline`。每个比较对象分别使用
自己的 `samples` 对场景、整体和报告指标加权；未启用或无有效配对样本的比较不会以零值
补入。尚未执行自动离线算法时，报告可保留 Offline 状态并明确标记“未执行”，但不会伪造
其准确度样本。

汇总内容包含整体及各场景准确度对比表，并按上述激活条件动态显示比较行。每个比较对象
显示 MAE、最大误差及当前阈值对应的准确度占比。

汇总同时包含按原始数据、参考数据和算法性能边界归类的异常统计。PPT 将异常归类和整体准确度拆成独立内容页，避免压缩多列准确度表；表格使用紧凑行高、按内容分配列宽，并将单元格文字水平和垂直居中。

Polar 警告不会替换原分析结论。存在局部 Polar 异常的文件仍保留原原因、证据文字和关键图表，并在 Markdown、PPT、JSON 和逐文件 CSV 中并列显示警告及异常位置。

算法原因只说明可能机制和证据，不输出算法优化方向。原始数据问题才会给出采集、佩戴、参考设备或时间对齐措施；没有可行原始数据措施时，报告为算法性能极限或证据不足。
