# check 命令金标数据检查设计

## 目标

为 `check` 命令增加心率和血氧参考（金标）数据质量检查。用户必须显式指定对应列名，未指定时不启用该类检查；检查结果沿用现有三态报告结构。

## 范围

- 心率金标：有效值必须在 `30-240`（含边界）；`0` 表示当前时刻无金标数据，非零样本占比低于 `70%` 时判定异常；阶跃和静止分别检测。
- 血氧金标：有效值必须在 `70-100`（含边界）；非零样本占比低于 `70%` 时判定异常；阶跃和静止分别检测。
- 阶跃检测检查相邻有效值的绝对变化，超过可配置阈值时判定阶跃异常，默认阈值为 `8`。
- 静止检测按连续相同值的帧数执行，不依赖时间戳；默认采样率 `25 Hz`，可由用户传入实际采样率覆盖。
- 阶跃时长默认 `5` 秒，可由用户传入覆盖；帧阈值为 `ceil(sample_rate * stale_seconds)`。
- 金标异常直接产生 `FAIL`，不增加 WARNING 比例容忍参数。

## 接口设计

新增 `check` CLI/API 参数：

- `--ref-hr-column`：显式指定心率金标列名；为空时不检查心率金标。
- `--ref-spo2-column`：显式指定血氧金标列名；为空时不检查血氧金标。
- `--ref-sample-rate`：金标采样率，默认 `25 Hz`，必须大于 0。
- `--ref-stale-seconds`：连续不变判定秒数，默认 `5`，必须大于 0。
- `--ref-step-threshold`：阶跃相邻变化阈值，默认 `8`，必须大于等于 0。

`CheckRequest` 保存这些参数；`run_check` 在列存在时调用 `DataChecker`。显式指定但列不存在时，文件按现有列结构不匹配逻辑跳过并记录原因。

## 核心算法

`DataChecker` 新增统一金标检查方法，参数包括列名、数据类型（HR/SpO2）、采样率、静止秒数和阶跃阈值：

1. 将列转换为数值，无法转换的值视为异常。
2. 统计范围异常数量；边界值正常。
3. 统计非零样本占比；小于 `70%` 判定异常。空列或无有效数值判定异常。
4. 检查相邻有效值绝对差是否大于 `step_threshold`，统计阶跃次数。
5. 使用连续相同数值的最长 run 判断静止；最长 run 的长度严格大于 `sample_rate * stale_seconds` 判定异常。
6. 返回名称分别为“心率金标”和“血氧金标”的 `CheckResult`，摘要分别说明范围、非零占比、阶跃次数和最长不变帧数。

## 报告与文档

现有报告根据结果名称动态生成列，因此新增结果会自动出现在 `check_report.csv` 和精简报告中。更新 `docs/cmd_check.md` 的参数、判断逻辑和示例；如有必要同步命令帮助文本。

## 测试策略

新增核心单元测试覆盖：

- HR/SpO2 边界值通过，越界值失败。
- 非零占比 `70%` 边界通过，低于 `70%` 失败。
- 采样率换算后的连续不变帧阈值，刚好阈值与低于阈值两种情况。
- NaN/非数值、空列和混合 0 数据。
- CLI/API 未指定列时不产生金标结果；指定缺失列时跳过并保留原因。
- 报告包含新增结果列。
